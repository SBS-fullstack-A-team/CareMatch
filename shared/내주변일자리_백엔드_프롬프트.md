# "내 주변 일자리" 기능 백엔드 구현 프롬프트

## 배경
케어매치 프로젝트에 "내 주변 일자리" 기능을 추가해야 해. 참고 서비스(요양나라)는 지도를 드래그해서 멈추면 자동으로 그 위치 기준 반경 10km 내 채용공고를 재검색해서 보여주는 방식이야. 우리도 같은 방식으로 갈 거야.

## 확정된 스펙
- 반경: 고정 10km (슬라이더 등 사용자 조절 기능 없음, MVP 범위 밖)
- 거리 계산: PostGIS 안 쓰고 Haversine 공식을 SQL에 직접 작성 (Neon PostgreSQL 확장 활성화 시간 절약 목적)
- 정렬: 거리 가까운 순(오름차순) 고정
- 페이지네이션: 기본 20건, page/size 파라미터로 확장 가능하게

## 요청 작업

### 1) DB 스키마 확인/수정
- 구인공고 엔티티(`JobPosting` 또는 실제 클래스명)에 `latitude`(Double), `longitude`(Double) 컬럼이 있는지 확인
- 없으면 마이그레이션 추가 (Flyway 쓰고 있으면 마이그레이션 스크립트로, 아니면 JPA 엔티티에 필드 추가)
- 기존 데이터에 좌표값이 없는 경우를 대비해 nullable 처리하고, null인 공고는 "내 주변 일자리" 결과에서 자동 제외되도록 쿼리 조건 처리

### 2) API 엔드포인트 추가
```
GET /api/jobpostings/nearby?lat={lat}&lng={lng}&page={page}&size={size}
```
- `lat`, `lng`는 필수 파라미터 (프론트가 지도 중심 좌표를 보냄)
- `page` 기본값 0, `size` 기본값 20
- 인증 불필요(비로그인도 조회 가능하게, 다른 검색 API와 동일한 정책으로 맞춰줘)

### 3) Repository 쿼리 구현 (Haversine)
Native Query 또는 `@Query`(nativeQuery = true)로 아래 로직을 구현해줘:

```sql
SELECT *,
  ( 6371 * acos(
      cos(radians(:lat)) * cos(radians(latitude)) *
      cos(radians(longitude) - radians(:lng)) +
      sin(radians(:lat)) * sin(radians(latitude))
  )) AS distance_km
FROM job_posting
WHERE latitude IS NOT NULL AND longitude IS NOT NULL
HAVING distance_km <= 10
ORDER BY distance_km ASC
LIMIT :size OFFSET :offset
```
- 6371은 지구 반지름(km) 고정값
- 응답 DTO에 `distanceKm` 필드를 추가해서 프론트가 "OOO에서 1.2km" 같은 텍스트를 표시할 수 있게 해줘 (소수점 1자리 반올림)
- 기존 구인공고 검색 API의 응답 DTO(SummaryResponse 등)와 필드 구성을 최대한 맞춰서, 프론트가 기존 카드 컴포넌트를 재사용할 수 있게 해줘

### 4) 페이지네이션 응답 형식
- 기존 검색 API(`PageResponse<SummaryResponse>`)와 동일한 응답 포맷을 재사용하거나, 최소한 구조를 맞춰줘 (content, page, size, totalElements, totalPages)

### 5) 테스트
- 임의의 좌표 기준으로 반경 10km 안/밖 공고가 정확히 필터링되는지 검증하는 테스트 케이스 작성
- 좌표가 null인 공고가 결과에서 제외되는지 검증하는 테스트 케이스 작성

## 참고 (프론트 연동 예정 사항 — 백엔드가 알아둘 것)
- 프론트는 카카오맵 SDK의 지도 이동 이벤트(디바운스 처리)로 좌표를 얻어서 이 API를 반복 호출할 예정
- 즉 이 API는 사용자가 지도를 조금씩 움직일 때마다 자주 호출될 수 있으니, 쿼리 성능(좌표 컬럼 인덱스 등)도 한 번 점검해줘
