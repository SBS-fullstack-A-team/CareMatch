## 1. "내 주변 일자리" 기능 — 이미 있는 것과 새 요청이 다름

팀원이 카카오맵 SDK 기반으로 새로 만들자는 프롬프트를 올렸는데, **백엔드에 이미 비슷한 기능이 구현돼
있고, 프론트는 의도적으로 그걸 안 쓰고 다른 방식으로 만들어져 있습니다.** 그대로 새 프롬프트를 실행하면
기존 구현과 어긋나므로, 아래 표로 뭐가 다른지 먼저 정리합니다.

| | 이미 있는 것 (백엔드) | 새 프롬프트가 요청하는 것 |
|---|---|---|
| 엔드포인트 | `GET /api/job-postings/nearby?lat=&lng=&radiusKm=&limit=` (`JobPostingController`, 테스트 `JobPostingNearbyTest` 있음) | `GET /api/jobpostings/nearby?lat=&lng=&page=&size=` (경로 표기도 다름) |
| 반경 | **가변** (`radiusKm` 파라미터, 기본 3km, 상한 50km) | **고정 10km** |
| 응답 형식 | `List<NearbyResult>` (페이지네이션 없음) | `PageResponse`(content/page/size/totalElements/totalPages) — 기존 검색 API와 동일 형식 |
| 거리 계산 | Java 코드에서 계산(`JobPostingService.distanceKm()`), bounding box로 1차 필터 후 정렬 | SQL Native Query에 Haversine 공식 직접 작성 |

**프론트는 이 백엔드 API를 아예 안 씁니다.** `NearbyJobsPage`(`/nearby`) 코드 주석:
> "프로젝트에 Geolocation·지도 SDK·좌표 데이터·거리 계산이 전혀 없으므로 '내 주변'은 **사용자가
> 직접 고른 지역**을 기준으로 처리한다. GPS·지도·거리 표기·거리순 정렬은 만들지 않는다"

→ 지금 `/nearby` 화면은 지도 없이, 사용자가 시·도/구·군을 고르면 일반 구인공고 목록 API(`sido`/`sigungu`
필터)를 재사용하는 방식으로 이미 만들어져 있음. 팀원 프롬프트의 카카오맵+GPS+자동재검색 방식과는
완전히 다른 접근.

### 결정할 것
- [ ] **카카오맵 방식으로 새로 갈지, 지금 방식(지역 선택)을 유지할지** — 팀 결정 필요. 새로 가면
      프론트 페이지를 거의 다시 만들어야 함
- [ ] 카카오맵으로 간다면: 백엔드 `nearby` 응답을 `List` → `PageResponse`로 바꿀지, 반경을 10km
      고정으로 바꿀지(또는 프론트가 항상 `radiusKm=10`으로 호출하면 백엔드 변경 없이 해결됨 — 이쪽이 더 쌈)
- [ ] 카카오맵 JavaScript SDK 키 발급 필요 (아직 없음)

## 3. 신규 기능 아이디어 (팀원 노트에서, 로드맵용)

두 사람 노트에서 **독립적으로 같은 아이디어**(신뢰도/인증마크)가 나온 걸 보면 팀 공감대가 있는 방향인 듯합니다.

### 신뢰도/인증 (수렴된 아이디어 — 경수+신영 둘 다 언급)
- 인증 마크: 본인인증 ✓ / 전화번호 인증 ✓ / 사업자·시설 인증 ✓ / 자격증 인증 ✓
- 이용 횟수 + 리뷰 기반 등급(업체·구직자 양쪽) — **리뷰/평점 테이블 자체가 지금 없음**, 완전 신규
- 신고 기능 (허위 채용공고 / 사기 의심 / 부적절한 내용 / 개인정보 노출 / 기타)

### 연락처 보호
- **안심번호** — 요양사·고객 각각 선택 가능한 중계번호(실제 전화번호 대신 안심번호로 노출). 인재정보 더미 프로필에도 이 형태로 적용 요청
- 전화번호 클릭 시 복사/바로 전화/메시지 선택 팝업

### 검색/탐색
- 가중치 필터: 추천수·리뷰·거리·연세·경력·성별·급여 순으로 정렬 — "거리" 축은 §1 내 주변 일자리(좌표) 기능과 연결됨
- 오늘 본 게시물 기록 (로그인 시), 관심 공고 저장과 별개
- 구인·구직 글 미리보기 기능

### 포인트/결제 — PG사 구체화됨
- **"PostOne" API로 결제 연동 예정** (신영 명시) → §4의 "PG사 미확정" 질문에 대한 답이 이미 있는 것으로 보임, 회의에서 확인만 하면 됨
- 회원가입 시 포인트 지급(3회분 정도), 업체 공고 등록 시 포인트 차감, 홍보(상단노출) 추가 포인트
- 마이페이지에 포인트 충전 버튼

### 마이페이지 확장
- 지원현황(내가 지원한 공고 + 내가 올린 공고 현황), 관심 공고, 오늘 본 공고 섹션 추가
- 희망조건 설정은 현행 유지

### UI/콘텐츠
- 글자크기 조절 — 슬라이더 + 좌우 화살표, **10단계**. ⚠️ **백엔드 `FontScale` enum은 지금 3단계(NORMAL/LARGE/XLARGE)뿐** — 10단계로 가면 enum이 아니라 숫자 스케일로 백엔드도 같이 바꿔야 함
- 배너 이미지 변경
- Footer(회사소개/이용약관/개인정보처리방침/고객센터) + FAQ·공지사항 더미 텍스트 채우기 — ⚠️ 이건 §4의 "약관이 샘플 텍스트라 법적으로 문제"랑 결이 다른 얘기입니다. FAQ/공지사항은 더미로 채워도 되지만, **이용약관/개인정보처리방침은 실제 서비스로 갈 거면 더미로 두면 안 됨** — 회의에서 이 둘을 구분해서 얘기해야 할 듯
- **고객센터 번호 통일: `1588-1234`** → `SUPPORT_TEL` 환경변수/시드값에 이 번호로 반영하면 됨 (지금 플레이스홀더 `1600-0000`)

### 정책 충돌 가능성 — 확인 필요
- 신영 노트: "회원가입 시 구직 희망하는 분들은 **자격증 첨부 필수**"
- 어제 팀 결정: 전화번호 인증을 **가입이 아니라 요양보호사 등록(자격증 등록) 시점**으로 미루기로 함(가입은 가볍게)
- 자격증 자체를 가입 때 필수로 받으면 이 결정의 전제("가입은 가볍게, 필요해지는 시점에 받는다")와 부딪힐 수 있어서 회의에서 조율 필요

## 회의에서 정할 것

1. **보안** — §0 자격증명 재발급 누가 언제 할지 (제일 급함)
2. **범위 정하기** — §3에 신규 아이디어가 꽤 많음(안심번호, 신고, 신뢰도, 가중치 필터, PostOne 결제,
   마이페이지 확장, 글자크기 10단계 등). 전부 이번 스프린트에 넣을 순 없으니 **MVP 유지 vs 이번에 추가**
   경계선부터 정해야 우선순위 논의가 됨
3. **정책 충돌** — 자격증을 가입 때 필수로 받을지, 어제 결정대로 등록 시점으로 미룰지 (§3 하단)
4. **"내 주변 일자리"** — 카카오맵 방식 새로 만들지, 지금 지역선택 방식 유지할지 (§1)
5. **담당** — "프로필 등록 저장"은 오늘 오후 해결됨(§2). 남은 건 "공고에 지원하기" 하나 — 프론트+백엔드
   둘 다 걸림. 자격증 업로드는 신영이 이미 진행 중(9/14 재개 예정)이라 새로 배정 안 해도 됨, 진행상황만 공유
6. **본인인증** — 카카오 위주로 갈지, SMS/이메일도 병행할지 (§4)
7. **간병인 서비스 확장** — 로드맵에 언제 넣을지 (지금 스프린트 범위 밖일 가능성 높음)
8. **CI 추가** — 프론트 typecheck/build를 PR 체크로 (비용 없음, 바로 가능)
